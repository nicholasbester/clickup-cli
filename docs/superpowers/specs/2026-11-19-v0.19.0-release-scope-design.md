# v0.19.0 release scope — design

**Date:** 2026-11-19

## Problem

`main` (bf6c5fe) carries 34 unreleased commits since v0.18.0. Three open issues
are already fixed there (#135 remove-dep query params, #130 subfolders, #148
Homebrew trust docs) but were never released. Two features on `main` must
**not** ship in v0.19.0:

- **Bring-your-own-app OAuth** (b81c0f2, merged by `5d295ea`). Mock-tested only;
  `docs/authentication.md` itself says a live round trip is required before
  release. Peer projects (triptechtravel/clickup-cli, nsxdavid/clickup-mcp-server)
  redirect to `http://localhost:PORT`, ours to `http://127.0.0.1:PORT` —
  unverified.
- **Enterprise audit-log request changes** (4b0029e, merged by `20765d4`):
  `before`/`after` page directions, `PREVIOUS`/`NEXT` aliases, MCP schema enums.
  Enterprise-only, unverified (parked issue #59).

## Owner decisions

- "Leave OAuth out of this release, focus on the other adjustments. Also leave
  out the enterprise requirement." Read as: exclude OAuth and the audit-log
  change (4b0029e). Owner also approved: PR → paired review → green CI →
  auto-merge → tag v0.19.0.

## Decision

Revert on `main`, preserve for later (paired investigation: Fable, Opus, Codex
Sol, Codex Astra — all four chose this or its scoped variant; Fable and Opus
proved it in scratch clones: build/clippy/fmt clean, 372 tests pass, and
reverting the reverts reproduces bf6c5fe exactly).

1. **Preserve**: refs `park/oauth-7` and `park/audit-log-59` at bf6c5fe, pushed
   to origin. (Existing `feat/issue-7-oauth` / `feat/issue-59-enterprise` are
   already ancestors of main, so merging them later restores nothing.)
2. **Revert OAuth**: `git revert -m 1 5d295ea`. Resolve the known mechanical
   conflicts (CLAUDE.md reference line, `src/commands/agent_config.rs` ×2,
   Cargo.toml, Cargo.lock, edit/delete on `src/commands/auth_oauth.rs` → delete).
   Include in the same commit the test edit
   `tests/test_combined_comment_features.rs` OAuth loop `[false, true]` →
   `[false]` so a later revert-of-revert restores it.
3. **Revert audit-log**: `git revert -m 1 20765d4`, separate commit.
4. **Do not revert `a1eb761`**: it also carries rustls 0.23.46,
   rustls-webpki 0.103.16, webpki-root-certs 1.0.10 security bumps that must
   stay. Its only source change lives in the deleted `auth_oauth.rs`.
5. **Prune direct dependencies** OAuth alone needed: `keyring`, `open`,
   `httparse`, `url`, `rand`, reqwest `form` feature; `tempfile` back to
   dev-dependencies — only where `rg` confirms no remaining use. Some (rand,
   url, httparse) legitimately remain as transitive deps. Never
   downgrade a surviving crate; regenerate the lock from bf6c5fe's lock with
   `cargo update -w`/build-driven pruning, not from v0.18.0's lock.
6. **Restore two corrections the OAuth revert would undo**: `CONTRIBUTING.md`
   MSRV line back to match `Cargo.toml` (1.88); `docs/commands.md` audit-log
   section lists real flags (v0.18.0 text advertised nonexistent
   `--type/--start-date/--end-date`). The `clickup setup` hint change is NOT
   re-applied (no standalone hunk; tests assert the old text).
6a. **cargo-deny**: main fails on RUSTSEC-2026-0543 (`chrono` unmaintained, no
   safe upgrade; direct dep driving `src/dates.rs`). Add a reasoned ignore in
   `deny.toml`; replacement tracked in a follow-up issue.
6b. **Merge method**: the release PR is merged with a merge commit (not
   squash) so the two revert commits stay individually revertable. After
   tagging, the orchestrator replaces the auto-generated GitHub release notes
   (which would list the OAuth/audit-log PRs) with the CHANGELOG section.
7. **Release housekeeping** (from final review `03-reconciled.md`):
   - CHANGELOG `[0.19.0] - <date>` with entries for every shipped user-facing
     change: #135, #130 (incl. `folder list --output json` now emits full API
     objects), #148, comment mentions + #125 hardening, `--link-preview`
     (#132), markdown blank-line/soft-break fix (27d7fae — move out of
     `[0.18.0]`), Dependencies (dirs 7, grouped bumps 5a1a715/bab1538/#154,
     rustls security patch). No OAuth or audit-log entries.
   - 143 → 144 MCP tools in docs/_config.yml, docs/index.html, npm/README.md
     (verify count from source).
   - CLAUDE.md / agent_config reference: add `--link-preview`; audit-log line
     matches the v0.18.0 behaviour that ships.
   - Version 0.19.0 in Cargo.toml, Cargo.lock, npm/package.json; compare links
     — follow release commit 566ae95's pattern.

## Goals

- v0.19.0 ships #130, #135, #148, comment features, deps; nothing OAuth, no
  audit-log request change.
- `git revert` of the two revert commits later restores both features exactly.
- `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`,
  CI (incl. cargo-deny, msrv, Windows) green.

## Non-goals

- Fixing OAuth (localhost redirect) or verifying audit-log on Enterprise.
- Extracting the general hardening that rode in the OAuth commit.

## Anti-goals

- No downgrade of TLS crates or any surviving dependency.
- No change to MCP tool count (stays 144).
- No touching `feat/*` branches or other worktrees.

## Constraints

- Work only in worktree `.worktree-labs/clickup-cli-d8d7887fe9/release-v0.19.0`,
  branch `release/v0.19.0`. Push only that branch and the two `park/*` refs.
- Tagging happens after merge, by the orchestrator.

## Owner decisions (2026-11-19, second round)

- "Enterprise requirement" = audit-log change 4b0029e → excluded.
- Defer the general hardening that came with OAuth (0600 atomic config writes,
  `CLICKUP_CONFIG`, token-free config parse errors, safer `agent-config init`
  token write) and the chrono replacement; open a GitHub issue for each.

## Calls made by the orchestrator (owner may overrule)

- Restoration is proven at the Milestone-1 tip (reverting the two revert
  commits reproduces bf6c5fe exactly, excluding design docs); later
  housekeeping may add small reference-text conflicts on re-land.
- Full revert (Fable/Opus) over scoped hand-removal (Codex): byte-identical
  auth surface to v0.18.0 is easier to review and restore.
